### D-001 磁力容器：磁力箱机制 + 原版资源容器收卡口径，做成城市专属卡
- 需求原话：「在工业革命DLC，也就是 city 这个地图，加一种类卡片叫磁力容器，主意为：铁条，铜条，科学，资源容器，受教育工人。功能类似于主大陆的磁力资源箱，可以自动吸取卡片，一些操作快捷键也都参考磁力资源箱就行」；另定「吸附范围 999，如果资源是从 A 卡片的输出接到了 B 卡片的输入，这种就不要吸附」。
- 结论：`MagneticContainer : MagnetChest`，继承吸附/截胡/取出免疫/Shift 10·Ctrl 1/3 路运输输出；覆写三处——收卡口径照原版 `ResourceChest`（只收 `CardType.Resources`，城市排除便便/铀，食物按 `FoodValue ≤ 0` 特例）、外观镜像原版 `storage_container`、`WantsCard` 排除正在管道运输的卡。
- 理由：用户要的是"城市里的资源容器 + 磁铁"，不是又一个磁力箱；收卡口径必须跟原版容器一致，否则城市资源流入箱子会错位。配方为 铁条 + 铜条 + 科学 + 资源容器 + 受教育工人（5 秒，工人不消耗；工人是城市里最贵的卡，消耗版还要处理合成后重建，收益不值）。
- 默认决定（未单独问用户）：运输输出 3 路、每 10 秒每路 1 张（对齐磁力箱）；容器垫底会吞材料，属硬约束（原版吞卡循环会把工人当"第一种资源"计入并销毁），因此只允许容器有父卡时叠工人，并加兜底补丁；取出时磁力族认领优先于弹射（`BounceTarget != null` 的卡不再被弹到侧面）。
- 被否方案：① 照磁力箱白名单收材料+食物+装备（城市口径不符）；② 允许在容器当根时把工人叠上去（会吞子卡，改为只在容器有父卡时放行，并加 `ContainerWorkerAbsorbGuardPatch` 兜底）。
- 日期：2026-10-22

### D-002 仓库一分为三：两个 mod 各一仓库，通用内容 + 反编译产物放私有仓库
- 结论：`stacklands-pro-max`（公开→后设私有）、`stacklands-diablo3` 各自只放 mod 本体；`stacklands-mod-common` 私有，装通用开发文档、JSON Schema 与 `decompiled/`（游戏反编译源码 + 参考 mod）。
- 理由：通用内容混在 Pro Max 里会随 mod 仓库一起暴露；反编译内容官方要求不公开分享，必须与公开仓库隔离。三个仓库并排放在同一目录，跨仓库用相对路径引用。
- 被否方案：把反编译产物继续放在工作区根、不入任何仓库（现状的缺点：换机器/重装即丢失，且无法版本化）。
- 日期：2026-10-24

### D-003 文档体系按「一事实一处」重构，一次只改一个项目
- 结论：Pro Max 采用 `AGENTS.md` + `docs/{REQUIREMENTS,DESIGN,PLAN,MEMORY,DECISIONS}` + `CHANGELOG.md`；旧文档（功能说明 / 开发与交接说明 / 环境准备 / 单篇决策 / 发布指南）提炼后删除，原文可从 git 历史取回。
- 理由：同一事实散在 README、功能说明、交接说明三处且互相矛盾；新会话要读完数百 KB 才能知道"现在做到哪"。大段版本历史压缩进 CHANGELOG，细节留在 git。
- 被否方案：保留原文件只加索引（两份索引都会过期）；把历史原文另存 `docs/archive/`（保留双份事实源）。
- 日期：2026-10-25

### D-004 仓库转为公开：清洗衍生内容 + 历史重建为单次提交
- 结论：`stacklands-pro-max` 改为**公开**仓库。本地历史整体重建为一次初始提交，GitHub 端**删库重建**（不用 force push）。
- 理由：原历史（50 个提交）里散落着从反编译产物提炼的逐字代码片段与"照抄 / 1:1 迁移"表述，按文件切不干净；仓库体量不到 1 MB、历史全是迭代提交，重建成本远低于 `git filter-repo` 逐提交改写。仓库从未公开过，删库重建没有 star / fork 损失。
- 内容边界（清洗标准）：**不留原版或第三方 mod 的源码原文、大段方法体、反编译行号**；机制说明、方法名、字段名、可访问性等描述性内容保留。注释与文档里的"照抄 / 照搬 / 1:1 迁移 / 逐条迁移"统一改为"对齐 / 参照其行为自行实现"。
- 被否方案：① `git filter-repo` 逐提交改写（要删的是散在注释里的文本，正则替换易漏且难以逐提交验证）；② 就地 force push 后转公开（旧对象仍可能按 SHA 取到，不如删库彻底）；③ 旧库改名归档（旧对象照样留在 GitHub 上）。
- 后续约束：新增代码注释与文档**不写源码原文、不写反编译行号**；反编译产物仍只放私有仓库 `stacklands-mod-common`，不进本仓库、不随 Mod 发布。
- 日期：2026-10-25

### D-005 取物落点：逐个候选点试"空地"，并覆盖食物容器

- 需求原话：「原版的资源箱和资源容器、食物容器，取出物品时，卡片的掉落位置也要改一下，改成优先往空地掉，这个在资源箱或者磁力资源箱上，应该是已经改过的，你看一下」。
- 结论：共用弹射 `ChestEject` 的落点从"朝外 1.2 格 + ±20° 随机"改成**逐候选点试空地**（距离 1.2/1.6/2.0 × 相对朝外的 0°/±30°/±60°/±90°/±135°/180°，先近后远、同圈先朝外），用「同场地任何卡都没压在这一格」判定；圈内全被围死才退回旧行为。新增 `FoodWarehouseEjectPatch` 把原版食物容器的"随机方向 `SendIt`"也纳入同一套；磁力箱点击取出的兜底同样改掉。
- 理由：旧实现只看方向不看占用——箱子挨着建筑或旁边已有一堆牌时，取出的卡正好压上去，还会被自动归堆吞掉（玩家观感是"点了没出来"）。"2 格内有同种牌堆就飞过去叠上"是 0.5.19 的独立需求（连续 Shift 取出要自动并堆），**优先级仍在最前**。
- 细节决定（未单独问用户）：判定盒取卡牌实际尺寸的 80%（擦边不算占用，否则相邻卡位之间永远没有空位）；还在飞（`Velocity` 有值）的卡按 `TargetPosition` 再算一次占用，避免连点两下落在同一点；沿用已有设置项「取出的牌往边上掉」当总开关（不新增开关）。
- 被否方案：① 纯随机角度多次重试（不可预测，观感像"乱飞"）；② 只按"离最近的卡的距离"筛（对建筑的大判定盒不准）；③ 新加一个"落点更远"的设置项（开关要克制，用户没这个诉求）。
- 日期：2026-10-25

### D-006 时间倍数沿用：记在两道前缀、还原放在 Update 后置；暂停中改 `prePauseSpeed`

- 需求原话：「在城市地图中，如果在一个回合（月亮年）中将速度调快了，下一个回合中速度会自动变成 1 倍。这个需要改成和上一回合速度一样」→「下一个-月-年沿用上一年的时间倍数，好像还有个自动暂停，这两个功能要在城市、海岛等多个地图全部生效」。
- 结论：`WorldManager` 上只有两处会把速度打回 1（`EndOfMonth` 结尾、`GoToBoard` 的过渡回调），两处都挂前缀记下 >1 的速度，`WorldManager.Update` 后置在"月结协程 / 过场动画 / 地图过渡全部结束且 `IsPlaying`"时还原。挂点与地图无关，所以城市 / 海岛 / 森林 / 主大陆一起生效。
- 理由：不在这两个方法的后置里直接改回来，是因为那样月结弹窗与换图过渡期间就是 5 倍（音乐音高等按 `SpeedUp` 变速，观感与原版不一致）。
- 与自动暂停的配合：Auto Pause 在过渡结束调 `TimePause()`，那一刻 `SpeedUp` 正是原版刚设的 1，于是"解除暂停后回到 1 倍"。这里在**暂停中**不改 `SpeedUp`（那等于替玩家解除暂停），改为覆盖 `GameScreen.prePauseSpeed`，解除暂停后即为原倍数。
- 被否方案：① 直接改 `EndOfMonth`/`GoToBoard` 的后置（弹窗期间就是快进）；② 每帧强制把 `SpeedUp` 维持在记忆值（会和玩家手动调 1 倍/暂停打架）；③ 只做月结不做换地图（用户明确要求多地图生效）。
- 日期：2026-10-25

### D-007 撤回「太阳能板 / 风力涡轮机可同种堆叠」

- 需求原话（先）：「城市中的太阳能板和风力涡轮机改成可以堆叠，但是还是不能互相堆叠」；（后）「算了，可以堆叠这个还是改回去吧」。
- 结论：已实现的 `CityEnergyStackingPatch`（`CanHaveCardOnTop` 后置，只放行同 id）**整条删除**，代码与文档都不保留该功能。
- 理由：用户试用后决定不要；保持原版口径（能源建筑一张一格）比多一条特例更稳。
- 备注：原版 `EnergyGenerator` 把 `DetermineCanHaveCardsWhenIsRoot` 设为 `true` 且 `CanHaveCard` 只认 `AcceptedCards`，所以"自己叠自己"恒为 false——如果以后还要这个功能，按同一条后置补丁重做即可（口径仍是"同 id 才放行 + 复算堆叠上限"）。
- 日期：2026-10-25
